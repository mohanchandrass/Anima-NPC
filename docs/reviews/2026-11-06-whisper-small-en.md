# Whisper small.en upgrade and latency review

Plan and implementation review used the development and design-review skills. Both are self-reviews; no independent reviewer was delegated.

## Reviewed plan

Upgrade the built-in English STT from base.en to the next size, small.en. Pin the official Systran model revision, update preparation/readiness labels and current setup documentation, and preserve the existing CPU INT8/two-thread/single-beam decoder, 20-second isolated-worker limit, audio cleanup and explicit external endpoint compatibility. Startup must prepare small.en even if base.en is cached; retain the old cache. No dependency, game protocol, state migration or native build change is required.

Acceptance: preparation uses the exact new repository/revision and existing restricted file list/cache root; missing new assets trigger preparation before serving; health names the active model; offline transcription never downloads; timeout/cancellation still reap workers. Tests include old-cache preservation and preparing/loading the new snapshot, existing load-repair/silence tests, speech routes and launcher defaults, then full offline regression.

Plan self-review: a larger model is an accuracy-capacity choice, not a measured accuracy or speed improvement. Preserve bounded work rather than increasing timeouts to hide regressions. Actual microphone accuracy, 15-second utterance processing within the 20-second limit, and game contention require target-machine measurements. Model weights remain ignored and are prepared by setup/connector startup, not committed.

## Latency findings and recommended sequence

These are source-based recommendations, not newly measured speedups. Measure end-of-player-speech to native playback start, with per-stage monotonic durations and correlated request/delivery IDs. Include STT load/decode, optional CV wait, retrieval, provider complete/repair, TTS and native delivery. Report warm p50/p90/p95, cold startup separately, timeouts/fallback/repair rates and game frame-time impact. The bridge's player-turn deadline begins after transcription, so current turn timings alone do not cover the full user wait.

1. **High: speech synthesis throughput.** `output/chatterbox.py` already owns a resident warmed worker. The saved November 5 CPU diagnostic took 19.67 seconds to synthesize a 2-second line; this is historical host-specific evidence, not the user's current performance. `adapters/skyrim/bridge.py` waits for full synthesis before staging the game command, including subtitles. Measure on the actual GPU/game workload first; select a faster supported speech backend if needed, or introduce a short synthesis budget with explicit subtitle fallback. Do not simply extend deadlines. Later first-sentence playback needs validated units, bounded buffers and explicit interruption/delivery/memory semantics; raw unvalidated model-token streaming is unsuitable.
2. **High: reload on every STT utterance.** `WhisperSpeech` launches a new process; `whisper.main` loads the model for every request after startup validation has already loaded/discarded it. A single resident warmed CPU INT8 worker should remove repeat import/load costs, especially with small.en. Preserve one active request/no queue, kill/reap on timeout/cancel, bounded recovery, and reject stale results. This is a recommended subsequent implementation, not part of this model change. Benchmark decoder threads against game frame times before increasing them; GPU STT must compete with TTS/game VRAM.
3. **High when CV is enabled: optional vision blocks text.** `run_turn` awaits `session.context_task`; `publish_context` captures/analyzes the frame before publishing trusted context. Thus a turn can wait for CV even when prompt attachment is disabled. Publish authoritative context first and analyze optional visuals separately; consume only an already-ready session/revision/TTL-valid descriptor, or use a short explicit wait for a visual-dependent request. Preserve context-before-turn ordering and prevent late descriptors from mutating an in-flight prompt.
4. **Medium: provider connections.** `ChatCompletionsProvider.generate` constructs/closes an AsyncClient on every attempt. Reuse a lifespan-owned client/connection pool with explicit shutdown and existing bounded admission, request timeout, response-size cap and no automatic retries. HTTPX documents connection reuse as avoiding repeated handshakes. Verify transport lifecycle with tests before implementing.
5. **Medium: model response work.** Benchmark the configured API provider on representative brief NPC turns, keep replies short, disable reasoning only where the backend supports it and quality is acceptable, and reduce repair rate with supported structured output. Preserve persona/knowledge constraints and compare quality as well as p95 latency. Existing authored/silent paths already avoid retrieval/model calls; retain them.
6. **Measure before tuning RAG/polling.** The research pilot recorded roughly 20 ms warm retrieval on a tiny authored corpus; that is not evidence for the current full corpus. Keep encoder/index warm and ingestion outside turns, measure actual scoped queries, then optimize only if material. Native command polling sleeps 100 ms; it is a smaller potential gain than multi-second speech/CV stalls. Do not increase poll traffic before measuring delivery delay.

Primary references: [official small.en history](https://huggingface.co/Systran/faster-whisper-small.en/commits/main), [faster-whisper CPU/INT8 and decoding documentation](https://github.com/SYSTRAN/faster-whisper), [HTTPX client connection pooling](https://www.python-httpx.org/advanced/clients/). These explain available mechanisms; their benchmarks are not Anima performance guarantees.
